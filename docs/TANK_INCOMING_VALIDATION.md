# Tank incoming validation

The page `tank_incoming.html` is an unlinked fight simulator. Survival means the tank's HP stays at -10 or above until the stated horizon. Average incoming DPS and scheduled HPS are diagnostics. They are not a substitute for the event queue.

Results stay estimated. A finite horizon is not a claim about an endless fight.

## Server functions

| Behavior | Source |
|---|---|
| Client death | `Mob::HasDied` in `zone/attack.cpp`: a client dies when `GetHP() < -10` |
| Unconscious, not the trial end | `Client::IsUnconscious`: HP from 0 through -10 |
| Avoid order | `Mob::AvoidDamage`: block, then parry, riposte, and dodge |
| Facing | `InFrontMob` is `MobAngle < 56`. Parry and riposte also reject ranged swings. Dodge requires front. Block's condition is only `GetSkill(SkillBlock)` |
| Miss check | `Mob::AvoidanceCheck` |
| Interval roll | `Mob::RollD20` and `Mob::CalcMeleeDamage` |
| Damage bonus | `NPC::GetDamageBonus` / `GetBaseDamage`, integer `di1k` rounding |
| Sheet AC | `Client::CalcMageloStats` path in `zone/client.cpp`: `ac_mitigation` is `GetMitigation(true)` |
| Combat AC | `Client::GetMitigation(false)`. Combat Stability raises the softcap. Raw shield AC is added to the cap once when Luclin is enabled |
| Displayed AC | `(avoidance + uncapped mitigation) * 1000 / 847` |
| Slow | `SE_AttackSpeed` in `zone/bonuses.cpp`, then `Mob::GetHaste` returns immediately on a negative v1 haste |
| Timer | `NPC::SetAttackTimer`. A delay under 401 is deciseconds. The timer is `delay / (haste/100)`, floored, with a 400 ms minimum |
| Round composition | `Mob::DoMainHandRound`, `DoOffHandRound`, `Mob::Flurry` |
| Area rampage | `HateList::AreaRampage`. With one hated mob in combat range, the current target is hit |
| Skill caps | `utils/sql/git/required/2022_08_03_skill_caps.sql`, level 65 |

Same-timestamp ordering is a simulator rule: every attack generated by that round, including a flurry or area rampage, is applied before a heal stamped at the same millisecond. `DoMainHandRound` does not interleave spells.

## Sheet cross-check

`generate_class_rankings.py` copies `ac_item`, `ac_shield`, `ac_avoidance`, `ac_mitigation`, `ac_total`, `weight`, `hp_max_item`, and the AGI parts when the export has them. Ranking scores still use `stats.hp` and `stats.ac`.

The page rebuilds uncapped mitigation and avoidance from worn item AC (ear through ammo), the level-65 defense cap, agility, race, and shield AC. Deltas against the export are shown. Worn spell AC and missing item rows are not invented. Defense is labeled assumed because the export has no defense column and `item_stats.json` has no skill-mod values.

Displayed AC is not the mitigation input.

## Quarm

Read from local `npc_types` id 223008:

| Field | Value | How it is used |
|---|---|---|
| level | 80 | offense, skills, triple-attack eligibility |
| class | 1 (Warrior) | triple attack can follow a double |
| mindmg / maxdmg | 1140 / 3800 | DB 1000, interval base 1400 |
| ATK / Accuracy | 500 / 750 | offense and to-hit |
| attack_delay | 38 | 3800 ms before haste |
| slow_mitigation | 25 | applied when a slow spell is selected |
| attack_count | -1 | one primary swing; `DoMainHandRound` treats a count of 1 or less as a single `Attack` |
| specials | `1,1^2,1^4,1,5,0,10^7,1^8,1^13,1^14,1^15,1^16,1^21,1^23,1^31,1` | dual wield on; area rampage chance 5 and damage percent 10; no flurry |

`potimeb/encounters/Phase6.lua` changes resists and AC only. That AC is Quarm's mitigation when players hit Quarm. It is not incoming tank mitigation.

Enrage is on the row (`2,1`) and is not modeled. It keys off Quarm's own HP, which this fight does not track. While enraged, the server also stops the defender's riposte. That uptime is omitted.

The two Mod2 rows "PoP boss" and "PoTime raid trash" keep their illustrative delays and attack counts. Those numbers are placeholders.

## Experimental Mod2s

The switch defaults off. Equipped totals from `data/item_mod2.json` still display.

When the switch is on, the page is labeled "Experimental Mod2 scenario".

- Shielding: `DB * (100 - percent) / 100`, cap 35, interval unchanged. `CalcMeleeDamage` does not read worn `GetShielding()`. This is the Mod2 damage-bonus hypothesis, not verified TAKP melee.
- Avoidance: the worn total is a miss-check percent. Combined with a spell avoidance percent by the server's best-value rule unless additive bonuses are requested.
- Accuracy, strikethrough, combat effects, spell shielding, and DoT shielding do not change incoming melee.

Mod2 ranking weights are unchanged.

## Healing

Jitter is uniform on the integer millisecond range `[-jitter, +jitter]`. The default is ±500 ms. It is not a 500 ms standard deviation.

A chain is rejected when a healer's personal cycle (`healers * spacing`) is shorter than the cast. The illustrative preset is four healers, 7,500 HP, a 10 second cast, and 3 second spacing: each healer's cycle is 12 seconds. Complete Heal's cast time and amount were not confirmed from a spell row in this tree, so the preset stays illustrative.

`actualHeal = min(scheduled, max(0, maxHP - currentHP))`. Overheal is tracked. A heal after death is not applied.

The spacing search reports a point estimate across several seeds and says when the confidence interval still crosses the target. It does not convert average incoming DPS into required HPS.

## Evidence gaps

- No combat-log comparison of Quarm hit sizes, double-attack rate, or area-rampage frequency.
- The area-rampage comment in `hate_list.cpp` says the one-target inclusion was not verified for AK. This simulator follows the checked-out branch.
- Character AA ownership and actual defense skill are not in the export.
- Defensive discipline values are user-entered. The `-50` / `-90` notes in `CalcMeleeDamage` are comments, not loaded spell rows.
- Enrage uptime and Quarm spell damage are not simulated.
- Class-rankings JSON already generated before this change has no `sheet` object until the rankings script is run again. The page still rebuilds from item AC and shows the export columns as absent.
